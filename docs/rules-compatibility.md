# Версии правил каскада

Подписка с узлами и файл правил — разные входы. Обновление правил не обновляет установленный `mihomo-build-config` или ядро. Старый сборщик не понимает политики `de-failover`, `pl-failover` и отменяет сборку; при запуске через systemd ошибка `ExecStartPre` блокирует весь сервис. Именно это произошло15октября2026 у внешнего пользователя.

## Контракт публикации

Совместимый publisher cactus-adm (изменение CASC-COMPAT) публикует два представления одного набора маршрутов:

| Файл | Клиент | Поведение |
| --- | --- | --- |
| `rules.yaml` | Любая ранее установленная версия | Прежние физические политики, например `de`; без автоматического резерва |
| `rules-v2.yaml` | Сборщик с поддержкой `cascade-fallbacks` | Политики `de-failover` и упорядоченные физические резервы; канарейки остаются физическими |

Это контракт совместимого publisher, а не утверждение, что новый URL уже развернут на конкретном сервере. Оба файла входят в `cascade.json`; локальный publisher пишет их в каталог артефактов и HTTP-каталог платформы. Получение `cascade.json` по SSH само по себе не создает HTTP endpoint на чужой установке.

Прежний URL остается совместимым со старыми сборщиками. Обновленный сборщик на прежнем URL тоже работает, но без использования резервов: для них нужен явный выбор `rules-v2.yaml`. Просто наличие метаданных не меняет физическую политику в правиле.

## Переход современной установки

1. Проверить поддержку: `grep -n 'cascade-fallbacks' /usr/local/sbin/mihomo-build-config`. Наличие строки — предварительный признак, окончательная проверка — сборка и фактический маршрут.
2. Убедиться, что сервер уже отдает валидный `rules-v2.yaml` нужного контура. URL может содержать секрет; не выводить его и содержимое `routing-rules.url` в общие логи.
3. Сохранить защищенные резервные копии `/etc/mihomo/routing-rules.url`, правил и текущего конфига. Поменять только URL правил на согласованный v2 endpoint; URL подписки с узлами не меняется.
4. Запустить штатный `mihomo-refresh`, проверить группы fallback, порядок физических выходов и открытие нужного сайта через реальный прокси. Канарейка конкретной ноды не должна переключаться на резерв.

Полный `install.sh` перезаписывает `config.base.yaml` и `local-rules.yaml`. При обновлении внешней установки сначала сохранить и учесть ее настройки SOCKS, allow-lan и локальных правил. `MIHOMO_ALLOW_SHRINK=1` не добавляет поддержку формата: на старом сборщике неизвестные политики превратятся в REJECT.

## Порядок выпуска publisher

Выкладка и изменения настроек парка требуют отдельного разрешения. Сначала на DEV проверить оба HTTP-ответа реальными старым и новым сборщиками, затем пройти такую же приемку PROD:

1. До смены содержимого прежнего URL создать v2 endpoint из проверенного текущего расширенного файла того же контура. Копию публиковать атомарно, файл должен быть валидным целиком.
2. Перевести известные современные установки на v2 и проверить реальные маршруты. Так переход прежнего URL на legacy не выключит на них резервирование. Краткое безопасное восстановление старых клиентов при необходимости можно выполнить раньше, но современные клиенты на старом URL в этом промежутке работают только через основные ноды.
3. Развернуть совместимый publisher и перепубликовать цели штатной командой `cascade:publish-routes`: сначала без `--send`, затем с разрешенной отправкой. Проверить legacy URL старым builder с существующим конфигом, v2 — новым; проверить повторную публикацию и восстановление каждого YAML.
4. Принимать выпуск по фактическому доступу старого клиента и сохраненному failover новых. Установленный код без перепубликации правил не исправляет инцидент.

Нельзя откатывать publisher на прежний код с включенной публикацией: он снова запишет несовместимый формат в `rules.yaml`. При аварии сохранить доступные legacy-safe и v2 файлы, остановить именно источники публикации маршрутов, восстановить совместимый publisher и только затем возобновить публикацию. Полный откат формата на старый URL не является безопасным откатом.

## Регрессионная проверка

`tests/published-rules-compat.py` принимает JSON payload реального publisher и путь к неизмененному историческому сборщику `dacb441`. Проверка запускает CLI в песочнице, использует синтетические узлы и не обращается в сеть:

```bash
python3 tests/published-rules-compat.py \
  --payload /tmp/cascade-payload.json \
  --legacy-builder /tmp/mihomo-build-config-dacb441
```

Проверяются исходный отказ старой версии с сохранением конфига, успешная сборка legacy, порядок физических резервов в современной версии и неизменность канареек. Это проверка генерации конфигурации; реальный egress при выкатке проверяется отдельно.
