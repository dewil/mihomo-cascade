# CASC-RULES-REQUIRED: не запускать каскад с примером правил

Статус: спека; следующий этап — независимые RED-тесты.

## Проблема

При нескачанном routing-rules.yaml сборщик принимает поставляемый пример с whatismyipaddress.com и MATCH,DIRECT за рабочую маршрутизацию. При отсутствии правил он сам подставляет MATCH,DIRECT. Сервис внешне исправен, но целевые сервисы получают прямой трафик.

## Требуемое поведение

Правила маршрутизации — обязательный вход сборки. Отсутствующий, пустой или состоящий из поставляемого примера файл не считается рабочим. Поставляемый пример определяется по разобранному списку четырёх правил, независимо от комментариев, кавычек и форматирования; перестановка тех же правил тоже не превращает пример в настоящую настройку. Файл с единственным MATCH,DIRECT также непригоден. Локальные правила не заменяют основной вход.

URL с host subscribe_domain считается незаполненной настройкой и немедленно даёт понятный отказ, даже если остались локальные правила. Отсутствующий/пустой routing-rules.url по-прежнему допускает настоящий локальный файл.

Скачивание сохраняет атомарность: ответ сначала проверяется как непустой набор правил, не пример и не MATCH,DIRECT; непригодный ответ не заменяет прежние настоящие правила. При сетевом сбое или непригодном ответе прежние настоящие правила используются с явным предупреждением. Если настоящего файла нет, сборка заканчивается ненулевым кодом до записи config.yaml, aliases и build-state. Имеющийся config.yaml сохраняется без изменений. Обхода этим требованиям через MIHOMO_ALLOW_SHRINK нет.

Сообщения причины называют отсутствие настоящих правил/незаполненную настройку без печати URL, который может содержать секрет. install.sh не должен печатать «Готово» при неуспешном старте или рестарте mihomo; service ExecStartPre уже использует сборщик. Штатная работа с настоящими правилами и контроль сокращения узлов сохраняются.

## Размены и границы

Выбран отказ вместо нового индикатора деградации. Не пытаемся определить полноту произвольных пользовательских маршрутов и не запрещаем осознанный DIRECT в настоящих правилах. Проверка полного YAML/конфига остаётся существующей проверке mihomo; новых зависимостей нет. Не меняем правила агрегатора и не проводим сетевой smoke к ChatGPT при каждом обновлении. Такая проверка нужна только в ручной живой приёмке новой установки. Боевой rollout — отдельная операция.

## Критерии приемки — tests/routing-rules-required.py

1. Нет файла, пустой файл, rules: [], единственный MATCH,DIRECT и поставляемый пример (также с другим форматированием/порядком) дают отказ, config/state/aliases.yaml не создаются или сохраняются побайтно.
2. subscribe_domain в hostname отвергается до скачивания правил, понятное сообщение без URL; корректный hostname, содержащий эти буквы как часть другого имени, не отвергается как плейсхолдер.
3. Реальные локальные правила без URL позволяют успешную сборку.
4. Сетевой сбой с реальными прежними правилами допускает сборку; с примером/без файла — отказ.
5. Пустой/примерный скачанный ответ не затирает реальные прежние правила; без реальных прежних — отказ.
6. Реальные скачанные правила заменяют пример и позволяют сборку.
7. Непригодные основные правила не спасают local-rules и ALLOW_SHRINK.
8. Ошибка сборщика препятствует успешному старту в поставляемом service; установщик не игнорирует неуспех start/restart и не печатает итог «Готово».

Все сценарии в песочнице MIHOMO_BASE без боевых путей, curl/chown/chmod подставные. Полная проверка: все tests/*.sh и новый Python-тест. Независимая сверка другой моделью до PR/мержа. Исходная находка: docs/dev/backlog/2026-09-22-pravila-ne-skachalis-proksi-vyglyadit-rabochim.md.

## Ручная приёмка при раскатке

Для новой установки один раз выполнить `curl -fsS --max-time 30 -x http://127.0.0.1:7890 https://chatgpt.com/cdn-cgi/trace` и сверить `loc=` с выбранным выходным узлом для chatgpt.com (по действующим правилам), а не со страной входной ноды. Сохранить только код ответа, ожидаемую/фактическую страну и результат сравнения; сырой ответ и адреса не публиковать. При отсутствии целевого правила сначала задать настоящее правило и выбранный узел; нельзя считать любой иностранный loc успехом. Проверка отдельно от полного тестового CI: без живой раскатки её результат не заявляется. Новая установка не принята в эксплуатацию до успешного сравнения; мерж исправления сам по себе не является такой приёмкой.
