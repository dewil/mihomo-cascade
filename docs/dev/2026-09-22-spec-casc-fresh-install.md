# CASC-FRESH: установка на чистую машину доходит до конца

Повод - три находки Андрея Мосиенко 21.09.2026 (карточка
`docs/dev/backlog/2026-09-21-nahodki-andreya-ustanovshchik.md`). Он ставил стек на чистую
Ubuntu как клиент, и установка сломалась дважды подряд. Обе поломки проверены по коду и по
боевым нодам.

## Что не так сейчас

**1. Установщик падает, если нет `/usr/local/sbin`.** Шаг 5 кладет четыре скрипта в этот
каталог четырьмя вызовами `install -m 755` (`install.sh:373-376`) без предварительного
`install -d`. Для каталога юнитов (`install.sh:41`) и для `/etc/mihomo`
(`install.sh:345-346`) установщик каталог создает, для `/usr/local/sbin` - нет. На типовом
образе каталог есть, поэтому дефект невидим; на минимальном образе или в контейнере установка
обрывается на середине, уже поставив бинарь, конфиги и geoip.

**2. Служба не может создать `cache.db`, и наш парк это скрывает.** Каталог конфигурации
создается как `root:mihomo` с правами 750 (`install.sh:345`), то есть процесс под
пользователем `mihomo` читать может, а создавать файлы - нет. При этом
`mihomo -d /etc/mihomo` (`etc/systemd/system/mihomo.service:13`) держит `cache.db` именно
там. Результат - `level=warning msg="[CacheFile] can't open cache file: open
/etc/mihomo/cache.db: permission denied"`.

Почему не всплыло раньше: на `ru2` и `ru3` файл существует с 30.03 и 23.04.2026, когда
каталог был доступен на запись, и принадлежит `mihomo:mihomo`. Записать в существующий файл
процесс может, создать заново - нет. Пока файл лежит, парк выглядит исправным; **любая новая
нода воспроизводит ошибку, а пропажа файла на старой превращает ее в такую же.** Сообщение
имеет уровень `warning`, служба поднимается, туннель работает - проверка "служба active"
отвечает одинаково в обоих состояниях.

Обходной путь `chown -R mihomo:mihomo /etc/mihomo` лечит симптом, отдавая службе на запись
весь каталог конфигурации, включая правила и ключи.

## Как должно быть

- **FR-CASC-FRESH-01.** Установщик создает каталог для скриптов, если его нет, и повторный
  запуск на машине, где каталог есть, ничего не меняет.
- **FR-CASC-FRESH-02.** На чистой машине служба создает свой кэш без предупреждения о правах.
  Проверяется не отсутствием строки в логе, а тем, что файл кэша появился в каталоге, куда
  службе разрешено писать.
- **FR-CASC-FRESH-03.** Каталог конфигурации остается недоступным службе на запись. Правка
  прав или владельца `/etc/mihomo` решением **не считается**: изменяемое состояние не должно
  лежать в каталоге конфигурации (FHS), а служба не должна иметь права перезаписать свои
  правила и ключи.
- **FR-CASC-FRESH-04.** Существующая нода переживает обновление без потери работоспособности:
  прежний `cache.db` в каталоге конфигурации не мешает и не приводит к двум разным кэшам.
  Содержимое кэша при этом терять допустимо - в нем сохраненный выбор узла и fake-ip, а группы
  у нас `url-test`, то есть выбор восстанавливается сам.
- **FR-CASC-FRESH-05.** Шаг установки скриптов и шаг подготовки каталога состояния проверяемы
  тестом без прав root - через `DESTDIR`, как это сделано у шага планировщика
  (`tests/scheduler-install.sh`).
- **FR-CASC-FRESH-06.** README описывает клиентское применение на Linux (mihomo как прокси для
  локальной сети) с **безопасным** рецептом: `allow-lan: true` и `bind-address` с адресом
  локальной сети либо ограничение фаерволом. Рецепт Андрея в исходном виде (`bind-address: "*"`)
  в документацию не идет: на машине с публичным адресом это открытый SOCKS5 на всех
  интерфейсах, то есть магнит для злоупотреблений и нарушение правил почти любого хостера.
  Оговорка про то, что за NAT звездочка безобидна, - в том же разделе.

## Принятые размены

- **Рабочий каталог службы остается `/etc/mihomo`.** У mihomo есть флаг `-f` для файла
  конфигурации, то есть можно было развести `-d /var/lib/mihomo -f /etc/mihomo/config.yaml` и
  унести в состояние заодно `geoip.metadb`. Это архитектурно чище и ровно то, что предлагал
  Андрей, но затрагивает все 12 боевых нод: `-d` задает и поиск geo-баз, значит обновление
  требует переноса файлов, иначе mihomo пойдет их скачивать заново. Дефект бьет только по
  новой установке, поэтому цена такой миграции сейчас выше выигрыша.
- **Состояние появляется отдельным каталогом**, а его связь с рабочим каталогом службы -
  деталь реализации. Требование FR-02 сформулировано по наблюдаемому результату (кэш создался
  в каталоге, куда можно писать), а не по способу.

## Не входит

- Перенос `geoip.metadb` и рабочего каталога службы в `/var/lib` (см. размен выше) - отдельная
  работа с миграцией парка.
- Разбор того, нужен ли нам кэш вообще: в конфиге нет ни `fake-ip`, ни `store-selected`,
  поэтому польза от него на каскадной ноде под вопросом. Но mihomo открывает файл кэша
  безусловно, и предупреждение появится независимо от нашего конфига.
- Клиентские сценарии сверх раздела в README: направление Linux-клиента мы не развиваем.

## Критерии приемки

Тест `tests/fresh-install.sh`, запускается без root, все записи в песочницу через `DESTDIR`:

- каталог для скриптов отсутствует - шаг установки скриптов создает его и ставит все четыре
  скрипта; код возврата нулевой;
- каталог для скриптов уже есть - повторный прогон не падает и не меняет прав каталога;
- шаг подготовки состояния создает каталог состояния с владельцем службы и правами, при
  которых служба может создать в нем файл; каталог конфигурации при этом остается без права
  записи для службы;
- прогон дважды подряд идемпотентен: второй раз ничего не ломает и не жалуется;
- юнит службы после установки несет то, что связывает службу с каталогом состояния (проверяется
  по факту в файле юнита в песочнице, а не по памяти).
